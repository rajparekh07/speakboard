# Token export format

The export is `assets/Export/speakboard-tokens.json`. It is validated by `assets/Export/validate-tokens.py` (standard library only), which mirrors `assets/Export/speakboard-tokens.schema.json` (JSON Schema 2020-12) and also runs it where `jsonschema` is available. Schema version `1.3.0`, token set version `0.2.2`. This page is enough to write the generator for the Swift constants and the core's metrics tables.

## Pinning

- The generator enforces one thing: the **SHA-256 of `speakboard-tokens.json`**. It refuses any file whose hash differs from the pin (`validate-tokens.py --expect-sha256`).
- Next to the hash, record the design system's URL, the publish label (for example "KEY-4 tokens v0.2.2") and the `tokenSetVersion`. Those are for people. The artifact's version id is not reliable for this: the same publish has reported two different ids.
- `tokenSetVersion` changes with every content change. `schemaVersion` changes only when the shape does: a minor bump only tightens validation or adds optional fields that generators may ignore; anything a generator must handle differently (a new axis shape, unit or provenance kind) is a major bump. Generators accept `1.x.y` and must fail on an axis shape, unit or provenance kind they do not know.
- The schema is generated together with each token set. It requires that set's device class ids, source ids and token ids, so validate a file only with the schema published beside it.

## Validating

```
python3 validate-tokens.py speakboard-tokens.json --schema speakboard-tokens.schema.json \
    --expect-sha256 <pinned hash> --no-measured
```

- Exit codes: 0 every check passed; 1 a check failed (an export that is not valid JSON counts as a failed check); 2 bad arguments, or an export or schema file that cannot be opened (or a schema that is not JSON).
- It needs only the Python standard library and runs two layers of checks, both always:
  1. **The schema mirror**: a plain-Python transcription of every rule in the schema, written to reach the same verdict as a JSON Schema validator. With `--schema` it reads the schema's device class, source and token id lists with plain JSON. Without `--schema` those lists are unknown and are not checked, so always pass it.
  2. **Extra checks** a schema cannot express, listed below.
- When `jsonschema` is installed and `--schema` is given, the real schema also runs as a cross-check. When it is not installed, the validator says so.
- **What is guaranteed:** layer 1 and the real schema agree on every input in `test-validator.py`, and both layers run with or without `jsonschema`. So on those inputs the verdict does not depend on `jsonschema`. The inputs are 61 named cases, plus about 37,000 mutations generated by walking the export and the schema (540 structurally distinct places): every structurally distinct key deleted, renamed and joined by an extra key, and every value replaced by wrong types, violating strings and numbers, and every enum and const value the schema uses. **What is not guaranteed:** agreement on inputs the test does not generate. Every difference the test has found is fixed. If you find another, it is a validator bug: the schema's verdict is the intended one.
- `test-validator.py <export folder> [--jobs N] [--skip-generated]` runs both parts and exits 1 on any failure. Part A runs each named case through the validator twice, once normally and once with `jsonschema` made unavailable. Each run must give the expected exit code, print no traceback, and, for a failing case, print the expected FAIL text, so a case cannot pass on a side effect. Part B needs `jsonschema`: it compares layer 1 with the real schema on every generated mutation, and runs layer 2 on each to catch crashes. It takes about 20 minutes on 4 cores; `--skip-generated` runs Part A alone in about a minute.

What the schema (and so layer 1) enforces:
- Top-level keys, `schemaVersion` `1.x.y`, a semver `tokenSetVersion`, `platform` `"iphone"`, every unit named in `units`, string descriptions in `units` and `toleranceUnits`, the three axes, and each source as exactly `{title, kind, url, note}`.
- Per iOS version: a two-digit key, and exactly `target` (a string), `referenceDeviceClass` (one of the device classes), `deviceClasses` and `tokens`. Each device class is `{screen, homeIndicator, models, provenance}`, with a `measured` or `estimated` provenance.
- Each token is exactly `{group, description, appleMatching, unit, axes, values}`, with an id matching the pattern.
- `axes` is exactly one of `[]`, `["appearance"]`, `["deviceClass","orientation"]`, and `values` holds exactly the allowed keys: every device class and both orientations, or both appearances.
- Each leaf is exactly `{value, unit, provenance}`. Its unit equals its token's unit. Its value has the right type: `count` is an integer, colours are `#RRGGBBAA` uppercase, weights are `UIFont.Weight` names, the family is `"system"`, and a `glyph-id` is a dotted lowercase string. Every patterned string (ids, colours, glyph ids, versions, the measured `ios`) also contains no whitespace, so a trailing newline fails.
- Provenance has exactly the keys of its kind (listed under Provenance below), with every required key present and every string in it non-empty. A tolerance is exactly `{plusMinus, unit}`, `plusMinus` is a number of at least 0, and the unit fits the value unit. Confidence and method come from their lists. `source` names a source in this file. `method: "derived"` needs a `derivation`. Source `no-basis` means method `placeholder` and confidence `none`.
- On `appleMatching` tokens every leaf is `measured` or `estimated`, and the two may be mixed while measurements arrive class by class. On other tokens every leaf is `invented`. The two never mix.
- `aliasOf` names a token in this file. `measured` needs `ios` (`NN[.N[.N]]`), `device` and `capture`.

**Extra checks (layer 2 only)**; a generator that does not run the validator must make these itself:
1. The file's SHA-256 matches the pin.
2. No token id is a prefix of another. No segment becomes a reserved Swift type name (`Type`, `Self`, `Protocol`, `Any`, `AnyObject`) as an enum, and no last segment is a Swift keyword.
3. Every number is finite (JSON Schema accepts `NaN`), and every `count` is an integer literal (JSON Schema accepts `3.0`).
4. Every `aliasOf` target has the same axes and unit, and the alias's value equals the target's value in every cell.
5. `deviceClasses` keys are in the order of `axes.deviceClass`.
6. Derived geometry. The identity tokens are `keyboard.keyArea.width`, `key.letter.width`, `keyboard.inset.bottom`, `keyboard.totalHeight`, `popup.key.riseLimit` and `key.space.width`; the ratio-based widths are `key.shift.width`, `key.delete.width`, `key.modeSwitch.width`, `key.utility.width` and `key.return.width`; the colour copies are `key.function.fillPressed` and `popup.fill`.
   - An estimated cell of any of these must be method `derived` with source `derived`, so relabelling a cell cannot skip the check.
   - Its value is recomputed from its inputs. For the identity tokens the worst-case tolerance is recomputed too, and the confidence must equal the lowest among the inputs, with a measured input counting as `medium`. A ratio-based width must not claim more confidence than `key.letter.width`; its ratio's own tolerance and confidence are not stored, so they cannot be recomputed. A colour copy must equal `key.letter.fill` in value, tolerance and confidence.
   - A **measured** cell of an identity token must agree with its recomputed value within its own tolerance plus the inputs' worst-case tolerance. If it does not, either an input or the measurement is wrong.
7. Method `derived` with a source other than `derived` is allowed only on `systemStrip.height`, `iphone-375x812`, portrait.
8. With `--no-measured`, no leaf and no device class is measured.
9. `summary` matches a recount.

## Top level

| Key | Type | Meaning |
| --- | --- | --- |
| `schemaVersion` | string | Shape version, semver. Generators accept `1.x.y`. |
| `tokenSetVersion` | string | Content version, semver. |
| `platform` | `"iphone"` | Only iPhone is defined. |
| `units` | object | Every value unit, with its meaning. |
| `toleranceUnits` | object | Every tolerance unit, with its meaning. |
| `axes` | object | The allowed keys per axis: `deviceClass` (ids), `orientation` (`portrait`, `landscape`), `appearance` (`light`, `dark`). |
| `sources` | object | Source id to `{title, kind, url, note}`. `kind` is `public-documentation`, `recall-unverified`, `derivation`, `none` or `capture`. In 0.2.2 every documentary source is `recall-unverified`: nothing was re-read. |
| `ios` | object | Keyed by iOS major version as a two-digit string. Only `"26"` so far. |
| `summary` | object | Counts of tokens by kind (`measured`, `estimated`, `measuredAndEstimated` for an Apple-matching token with both, `invented`), of values by kind, and of estimated values by confidence and by method. Informational; the validator recounts it. |

## Per iOS version: `ios["26"]`

- `deviceClasses`: id to `{screen: {width, height, unit: "pt", orientation: "portrait"}, homeIndicator, models[], provenance}`. Ids read `iphone-<width>x<height>` in portrait points. Landscape width is the portrait height.
- `referenceDeviceClass`: the class the design system page shows.
- `tokens`: token id to token.

## A token

```json
"key.letter.height": {
  "group": "geometry.keys",
  "description": "Height of every key in the four rows ...",
  "appleMatching": true,
  "unit": "pt",
  "axes": ["deviceClass", "orientation"],
  "values": {
    "iphone-393x852": {
      "portrait":  {"value": 42, "unit": "pt", "provenance": {"kind": "estimated", "source": "pre26-keyboard-recall",
                    "tolerance": {"plusMinus": 3, "unit": "pt"}, "confidence": "low", "method": "recalled"}},
      "landscape": {"value": 32, "unit": "pt", "provenance": {"...": "..."}}
    }
  }
}
```

- **Ids** are dotted lowerCamel segments, `^[a-z][a-zA-Z0-9]*(\.[a-z][a-zA-Z0-9]*)+$`. Every segment but the last becomes a nested enum with its first letter capitalised; the last becomes a `static` member. `key.letter.height` becomes `Tokens.Key.Letter.height`. Tokens for one key all live under `key.<name>`.
- **`axes`** lists how `values` nests, outermost first: `[]` (`values` is a leaf), `["appearance"]` (`values.light`, `values.dark`) or `["deviceClass", "orientation"]` (`values[classId].portrait`, `.landscape`). Every allowed key is present.
- **Which tokens vary.** Every Apple-matching length, ratio and type size has `["deviceClass","orientation"]`, even where the estimate is one figure for every iPhone, so a measurement that differs by class never changes a constant into a function. Colours have `["appearance"]`. Weights, the typeface, counts and timings have `[]`. Invented constants that are ours by design (mic dot, level ring, dictation timings) have `[]` on purpose; making one vary would be a breaking change and needs a major `tokenSetVersion`.
- **A leaf** is `{value, unit, provenance}` and nothing else.

## Units

| Unit | Value | Swift |
| --- | --- | --- |
| `pt` | number | `CGFloat` |
| `ms` | number | `TimeInterval` in seconds (divide by 1000) |
| `ratio` | number | `CGFloat` |
| `count` | integer | `Int` |
| `srgb-hex8` | `#RRGGBBAA`, uppercase, straight alpha | `UIColor(red:green:blue:alpha:)`; pair light and dark into one dynamic `UIColor` |
| `uifont-weight` | `UIFont.Weight` name | `UIFont.Weight.<name>` |
| `font-family` | `"system"` | `UIFont.systemFont(ofSize:weight:)` |
| `glyph-id` | dotted lowercase string | key into our own icon set |

## Provenance

- `measured`: `ios` (exact, e.g. `"26.1"`), `device` (model and class, or the simulator runtime), `capture` (CI run, file path and content hash); optional `capturedAt`, `method`, `tolerance`.
- `estimated`: `source`, `tolerance` `{plusMinus, unit}`, `confidence` (`medium`, `low`, `none`) and `method`; optional `derivation` and `note`. Methods:
  - `recalled`: a figure remembered from the iOS 11–18 keyboard or from Apple's documentation.
  - `derived`: computed by `derivation`. When the source is `derived`, the inputs are other tokens, and this tolerance rule applies: the sum of each input's tolerance times the absolute value of its coefficient, rounded up to 0.1 (worst case, deliberately wide), with confidence the lowest among the inputs. A measured input counts with its own tolerance, or 0 if it gives none. When the source is anything else, the inputs are an outside figure (only `systemStrip.height` on `iphone-375x812` in portrait), and the tolerance is a judgement stated in the note.
  - `assumed`: carried over from portrait or another class with no basis of its own.
  - `guessed`: a number picked inside a qualitative impression.
  - `placeholder`: no basis at all (source `no-basis`, confidence `none`). The tolerance spans the plausible range.
- `invented`: `rationale`; optional `decidedIn` and `aliasOf`.

## Aliases

An invented value with `aliasOf` deliberately equals another token's value, for example the mic key at rest taking `key.function.fill`.

- The export always holds the resolved value, and the validator fails if it differs from the target's.
- **The generator emits a reference to the target constant, never the copied number**, in the same form the target takes. For a device-class token (for example `mic.glyphSize`, an alias of `key.function.glyphSize`): `static func glyphSize(_ c: DeviceClass, _ o: Orientation) -> CGFloat { Tokens.Key.Function.glyphSize(c, o) }`. For an appearance token (for example `dictation.rest.keyFill`, an alias of `key.function.fill`): `static var keyFill: UIColor { Tokens.Key.Function.fill }`. Both rules together mean an alias can never silently differ from its target.

## What a generator emits

- **Swift constants** (extension, build time, no runtime parsing): one nested enum per id segment, plus a `DeviceClass` enum generated from `deviceClasses`. Tokens with no axes become `static let`. Device-class tokens become a `static func` of `(DeviceClass, Orientation)`, a `switch`. Appearance tokens become one dynamic `UIColor`. Emit provenance as a doc comment.
- **No-basis values.** Deprecation applies to a whole declaration, so use it only for a token whose **every** cell has `confidence: "none"`: mark that declaration `@available(*, deprecated, message: "placeholder, no basis")`. A token with any usable cell is never deprecated. Its `confidence: "none"` cells are listed in the doc comment, and the generator emits a companion `isPlaceholder` function taking the token's axis values (`(DeviceClass, Orientation)` or the appearance), so a caller or a debug assertion can tell a placeholder cell from a usable one. In 0.2.2 the fully deprecated tokens are `keyboard.backdrop.topCornerRadius`, `key.delete.wordModeAfter` and `key.space.doubleTapPeriodWindow`; 15 tokens mix none and usable cells (14 by device class and orientation, and `key.shadow.color`, whose dark value has no basis).
- **Metrics tables** (core): one row per device class and orientation, one column per token whose axes are `["deviceClass","orientation"]`, each cell with value, tolerance, kind and a placeholder flag (`confidence: "none"`). Tolerance: an estimated cell's `plusMinus`; a measured cell's `plusMinus`, or 0 when it states none (the same reading the derived rule uses); an invented cell has no tolerance, written as `null`, because its value is a decision, not an estimate.
- Both outputs carry a header naming the pinned hash and token set version, and CI fails if they were edited by hand.

## When measurements arrive

- A measured value replaces an estimated leaf in place: same id, same unit, `provenance.kind` becomes `measured`. Measurements may arrive for some device classes before others; a token then holds measured and estimated cells together and counts as `measuredAndEstimated` in the summary.
- **What the measured-tokens ticket (T43) must change in the build source.** Today `assets/Export/source/build_export.py` cannot take a measurement: every leaf is built by an estimate function (`e_area_h`, `e_keyh`, `e_gap` and so on), and every derived cell calls those functions directly, not the stored leaves. T43 must (1) add a way to record a measured leaf, with `ios`, `device`, `capture` and a tolerance, that overrides the estimate for its cell; (2) make every derivation (`e_kaw`, `e_letter`, `e_bottom`, `e_total`, `e_rise_limit`, `e_space`, `e_ratio`, `from_letter`) read its inputs from the resulting leaves, so a measured input reaches the cells derived from it, with the tolerance and confidence rule applied to the measured values; (3) count summary buckets as it does now. Until then a measurement entered by hand into the JSON leaves derived cells stale, and the validator fails on them, so nothing goes wrong silently.
- Derived values are recomputed by the build, not edited by hand. The validator fails if a derived cell no longer matches its inputs.
- Aliases follow automatically: the build re-resolves them, the validator fails on any mismatch, and generated code already references the target.
- A new iOS major version is a new key under `ios`, copied from the previous one and re-measured.
- None of this changes the schema's shape. The generated id lists change, so the schema is republished with the token set.
